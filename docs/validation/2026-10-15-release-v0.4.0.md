## 已发布镜像的监控链路

使用只有全局 `metrics.read` 的 Key，实际通过 Prometheus 抓取、真实耗时直方图与正值 p95、Grafana 8 个面板和数据源查询、3 条告警规则加载、OTel Collector 采集再导出、VictoriaMetrics 直接抓取、Alloy remote_write 与 Loki 真实 JSON 日志查询。匿名抓取为 401，采集 Key 读取配置为 403；测试 Owner 吊销 Key 后，Prometheus 的 `up` 变为 0。

[完整检查结果](release-v0.4.0/2026-10-15/observability.json) · [PromQL 数据](release-v0.4.0/2026-10-15/promql.json)。p95 数值只是少量验收流量的结果，不是负载基准。

首次验收只发送短流量，虽然计数已采集，p95 没有得到正值。主分支脚本现会在查询期间继续发真实请求；修复后记录到跨采样的计数 `20 → 22 → 23` 和正值 p95。第二次验收遇到 Grafana 冷启动关闭连接，脚本原来直接退出；新增有界重试后，完整干净环境验收通过。独立真实 HTTP 回归也确认修复前首次关闭即失败，修复后第二次请求成功。两次失败记录与前后脚本均保留在证据归档中。

这两项发布后的修复只修改验收脚本，未改变 `v0.4.0` 二进制。监控验收请使用[主分支脚本](https://github.com/ALVIN-YANG/senix/blob/main/scripts/check-observability.py)；标签内旧脚本仍可能出现上述误报。[连接关闭回归](release-v0.4.0/2026-10-15/cold-http-retry.json)。
