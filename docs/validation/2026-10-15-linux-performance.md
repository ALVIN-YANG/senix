# GitHub Linux runner 性能基线

日期：2026-10-15。来源为 [GitHub Actions 实际运行](https://github.com/ALVIN-YANG/senix/actions/runs/38707502445)，测试固定在干净提交 `af40d95a7335889c51af4d3771b1a290c6474499`，release 镜像由该次工作流构建。该基线早于 MCP 规划版本校验增量，不代表后续提交已重新压测。

这次测量补充了 Linux AMD64 环境证据。GitHub 托管 runner 不是独占生产服务器；与 [ARM64 本机基线](2026-10-15-performance.md) 的硬件和负载条件不同，不能把数值差异解释为优化收益。

## 环境与方法

- Ubuntu 24.04.5 LTS，Linux `6.17.0-1022-azure`，x86_64；Docker 28.0.4，4 CPU、15.62 GiB 内存。精确值见 [metadata.json](benchmarks/2026-10-15-linux/metadata.json)。
- Senix、k6、后端各限制 2 CPU / 1 GiB，共享这台 4 CPU runner；Node 24 单 worker，固定 1 KiB 响应，同一 Docker bridge 网络，Keep-Alive，无宿主机端口转发。
- 四种路径 × 1/32/128 VU × 3 次，共 36 次测量；每档预热 3 秒，每次测量 10 秒。闭环、无额外请求间隔；固定顺序为直连、HTTP、HTTPS/H2、100 路由，未随机交错。
- 默认 Pingora 配置，逐请求访问日志与外部采集关闭，指标常驻计数保留。HTTPS 使用自签名测试证书，仅负载器关闭证书校验。
- 测量时间为 `2026-10-15T08:46:27Z` 至 `2026-10-15T08:53:26Z`。Senix 镜像 ID 为 `sha256:1b0ca81f6d0fbe1889ad8ef7dfbf52614994ba533ae9f42a4b33c1b51967025f`；k6 2.3.0、Node 镜像的精确 digest 已归档。

## CPU 与内存

| 场景（32 VU） | Senix CPU 窗口均值中位数 | RSS 最大结束样本 | 进程 HWM |
| --- | ---: | ---: | ---: |
| HTTP | 91.1% | 25.1 MiB | 25.1 MiB |
| HTTPS / H2 | 93.7% | 35.1 MiB | 35.1 MiB |
| HTTP / 100 路由 | 90.3% | 24.6 MiB | 24.6 MiB |

单核心 CPU 为 100%，由 cgroup CPU 计数增量除以采样窗口计算。窗口包含负载器容器启动和退出，不是严格 10 秒负载阶段的均值。RSS 是结束时刻样本；HWM 是进程整个生命周期的峰值，包含此前预热和其他并发档位。网关进程在常规场景间复用，100 路由场景使用新进程。资源数据不能作为每次运行独立的内存峰值或生产资源承诺。
