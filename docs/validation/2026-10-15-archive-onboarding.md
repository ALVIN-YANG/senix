# 四平台打包与归档入门验收

日期：2026-10-15。二进制源码为 `a3d2c14135ce5149e48493109bf179881161fdca`，程序仍报告 `senixd 0.4.0`。这些是包含尚未发布更新的 CI 归档，标签为 `edge-<commit>`，不是已发布的 `v0.4.0` 归档，也不是 `v0.4.1` 成品。

## 发现与修复

原归档只带程序、仓库首页 README、许可证和示例配置；README 引用的英文页、图片及多数文档没有随包提供。四份实际下载的归档都存在这项问题。

打包脚本现使用独立的中英文入门模板，说明系统与后端前提、密码要求、一次性引导与 Owner 初始化、前台启动、真实请求检查、失败重试和持久数据。在线文档使用完整 URL，固定到版本标签或 `edge-<commit>` 的源码提交。版本参数限制为可用于归档名和文档链接的字符，非法参数在写入输出目录前被拒绝。

## 构建和实际运行

[四平台打包工作流](https://github.com/ALVIN-YANG/senix/actions/runs/38753251787) 在上述源码提交成功完成 macOS / Linux 的 x86_64、ARM64 构建。两种 Linux 归档均在各自原生 runner 的 Rocky Linux 9（glibc 2.34）环境中执行 `--version`。该次运行的镜像及 Release 发布任务跳过。

下载四份原始 CI 归档后，在隔离目录中用修复后的脚本重新打包。每份归档都检查实际文件类型、说明双语内容、占位符替换与文档链接；重打包前后的二进制逐字节一致。原始及新归档、二进制的 SHA-256 均记录在 [归档检查](archive-onboarding/2026-10-15/archives.json)。因此四平台构建证据属于原始提交，模板与打包修复的证据属于本机重打包，未将两者混称为同一轮远端构建。

## 包内说明的真实执行

macOS ARM64 上从新归档解包，读取并执行其中四个 Bash 代码块。只按说明替换后端地址与空闲端口；示例健康检查参数保留。检查包括正常初始化，以及先输入弱密码、保留同一数据库且不重建引导凭据后成功重试的两种情况。

- 通过伪终端核对密码输入期间关闭回显、之后恢复回显，终端输出不含测试密码。
- Owner 登录返回 200；Owner 创建后，原一次性引导 Key 访问管理接口返回 401；数据库权限为 `0600`。
- 说明中的 curl 检查得到进程健康和真实后端响应。
- 停止后修改启动 JSON 的域名，再以同一数据库启动：原 Owner 可登录，已保存域名仍为 200，新的启动文件域名为 404。

[两种初始化结果](archive-onboarding/2026-10-15/guide.json)。归档版本参数另检查空值、路径穿越和模板分隔符输入，均在输出写入前被拒绝；Bash 代码块和打包脚本语法通过。

## 边界和复现材料

本轮没有改动代理或管理接口实现，也未替换已发布产物、推送镜像或创建新版本标签。新版公开发布仍待授权。macOS ARM64 上的指南交互结果不扩大为所有终端与系统的交互保证；没有重测性能、流式容量或长期稳定性。

测试程序、后端和临时数据库均属于隔离验收；私密状态已清理，未改动用户原有服务。[检查摘要](archive-onboarding/2026-10-15/checks.json) · [脱敏运行脚本与日志](archive-onboarding/2026-10-15/logs-and-fixtures.zip) · [SHA-256](archive-onboarding/2026-10-15/SHA256SUMS)。归档保留在忽略的本机验收目录；CI 下载归档受 GitHub 的 artifact 保留期限制。
