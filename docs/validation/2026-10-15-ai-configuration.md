## 完整操作证据

当前 AI 助手通过真实 HTTP MCP 端点读取 Snapshot 1，仅修改 `demo-route` 的 Host，保留另一条路由。浏览器中使用测试 Owner 签发“配置协作”Key、核对候选内容并批准，随后 AI 通过 MCP 检查批准状态、应用计划并重新读取配置。

- 计划：`f19b25aa-d75c-4764-ab53-cd8b252eff11`，批准者为测试账号 `admin`。
- 批准前应用返回 `CHANGE_APPROVAL_REQUIRED`，原域名继续返回后端 A。
- 批准后 Snapshot 版本为 2，`preview.senix.local` 返回 HTTP 200、后端 A。
- 无关路由 `untouched.senix.local` 返回 HTTP 200、后端 B，配置内容与修改前一致。
- 原域名 `demo.senix.local` 返回 HTTP 404。
- E2E 另行确认只读 Key 无法规划或应用、实例范围 Key 无法读取全局配置、吊销后返回 401、AI 不能批准、重复应用返回原版本、过期基线返回 `STALE_PLAN`。

Linux ARM64 容器内再次完成读取、规划、拒绝未批准应用、测试 Owner 批准、MCP 应用和真实请求检查。计划为 `24c144b9-3763-4af0-b033-727adb3564d6`，版本从 1 变为 2。

独立 Compose 项目验证了首次启动、运行中重跑、保留卷停止后重启，以及使用新域名重跑、重启；修改后的配置和版本 2 均保留。测试使用 18080/19080，保留了机器原有的 8080 服务。重跑过程中发现并修复了临时容器静态 IP 冲突和已初始化状态识别问题。
